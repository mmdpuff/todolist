📌 معرفی پروژه

اپلیکیشن Todo App یک برنامه ساده اما کاربردی برای مدیریت کارهای روزانه است. این پروژه با استفاده از فریم‌ورک Flutter طراحی شده و هدف آن تمرین مفاهیم مهم برنامه‌نویسی موبایل مانند مدیریت وضعیت، ساخت ویجت‌های اختصاصی، کار با فرم‌ها، نمایش لیست، حذف آیتم‌ها، و ذخیره‌سازی داده‌ها در حافظه محلی دستگاه است.

این برنامه برای کاربرانی طراحی شده که می‌خواهند کارهای روزانه خود را ثبت کنند، برای هر کار توضیح بنویسند، اولویت مشخص کنند، تاریخ انجام انتخاب کنند و وضعیت انجام شدن یا نشدن هر کار را مدیریت نمایند.

ظاهر برنامه به صورت کاملاً فارسی و راست‌چین طراحی شده و از رنگ‌بندی مدرن، کارت‌های زیبا، گرادیان، انیمیشن‌های نرم و طراحی مبتنی بر Material Design 3 استفاده می‌کند.

این پروژه کمک می‌کند مفاهیم زیر بهتر یاد گرفته شوند:

- استفاده از StatefulWidget

- استفاده از مدل داده‌ای

- استفاده از Bottom Sheet

✨ امکانات اصلی برنامه

این اپلیکیشن امکانات مختلفی برای مدیریت کارهای روزانه دارد.

➕ افزودن کار جدید

کاربر می‌تواند با زدن دکمه «کار جدید» یک Bottom Sheet زیبا باز کند و اطلاعات کار جدید را وارد نماید.

اطلاعات قابل ثبت برای هر کار شامل موارد زیر است:

- عنوان کار
- توضیح کوتاه
- اولویت
- تاریخ انجام
- وضعیت انجام شدن

---

✏️ ویرایش کارها

هر کار دارای منوی گزینه‌ها است که کاربر می‌تواند از طریق آن گزینه ویرایش را انتخاب کند. هنگام ویرایش، اطلاعات قبلی کار داخل فرم قرار می‌گیرد و کاربر می‌تواند آن‌ها را تغییر دهد.

موارد قابل ویرایش:

- عنوان
- توضیح
- اولویت
- تاریخ انجام

---

🗑️ حذف کارها

کاربر می‌تواند یک کار را حذف کند. حذف از طریق دو روش انجام می‌شود:

1. منوی گزینه‌ها
2. کشیدن آیتم به سمت چپ با استفاده از Dismissible

بعد از حذف، یک SnackBar نمایش داده می‌شود که امکان بازگردانی کار حذف‌شده را فراهم می‌کند.

---

↩️ بازگردانی کار حذف‌شده

بعد از حذف یک کار، کاربر می‌تواند با زدن گزینه «بازگردانی» آن را به لیست برگرداند. این قابلیت باعث می‌شود اگر کاربر اشتباهی یک آیتم را حذف کرد، بتواند سریعاً آن را بازیابی کند.

---

✅ تغییر وضعیت کار

برای هر کار یک Checkbox وجود دارد. با زدن آن، وضعیت کار بین دو حالت تغییر می‌کند:

- در حال انجام
- انجام شده

اگر کاری انجام شده باشد، ظاهر آن تغییر می‌کند و عنوان آن خط خورده نمایش داده می‌شود.

---

🎯 تعیین اولویت

برای هر کار می‌توان یکی از سه سطح اولویت را انتخاب کرد:

اولویت| توضیح
کم| برای کارهای عادی و کم‌اهمیت
معمولی| برای کارهای روزمره
مهم| برای کارهای ضروری و مهم

هر اولویت رنگ مخصوص خودش را دارد تا کاربر بتواند سریع‌تر اهمیت کارها را تشخیص دهد.

---

📅 انتخاب تاریخ انجام

کاربر می‌تواند برای هر کار یک تاریخ انجام انتخاب کند. این تاریخ در کارت مربوط به کار نمایش داده می‌شود.

همچنین در فرم افزودن یا ویرایش، امکان پاک کردن تاریخ انتخاب‌شده وجود دارد.

برنامه دارای سه فیلتر اصلی است:

فیلتر| کاربرد
همه| نمایش تمام کارها
فعال| نمایش کارهایی که هنوز انجام نشده‌اند
انجام‌شده| نمایش کارهایی که تکمیل شده‌اند

فیلترها با ظاهر زیبا و انیمیشن نرم طراحی شده‌اند.

📊 نمایش درصد پیشرفت

فرمول محاسبه پیشرفت:

اگر هیچ کاری در لیست وجود نداشته باشد، مقدار پیشرفت برابر صفر نمایش داده می‌شود.

💾 ذخیره‌سازی داخل کش دستگاه

یکی از مهم‌ترین قابلیت‌های نسخه جدید پروژه، ذخیره شدن اطلاعات داخل کش دستگاه است.

برای این کار از پکیج زیر استفاده شده است:

shared_preferences

با این قابلیت، اگر کاربر برنامه را ببندد و دوباره باز کند، اطلاعات قبلی از بین نمی‌رود.

مواردی که ذخیره می‌شوند:

- تاریخ ایجاد
- تاریخ انجام

🧠 چرا از SharedPreferences استفاده شده است؟

در پروژه‌های ساده، زمانی که حجم داده زیاد نیست، استفاده از "shared_preferences" یکی از ساده‌ترین و بهترین روش‌ها برای ذخیره اطلاعات سبک است.

در این پروژه، لیست کارها به JSON تبدیل می‌شود و به صورت یک رشته داخل حافظه محلی ذخیره می‌شود.

مزیت‌های این روش:

- پیاده‌سازی ساده
- مناسب برای پروژه‌های آموزشی
- بدون نیاز به دیتابیس سنگین
- سرعت مناسب
- قابل فهم برای افراد مبتدی
- مناسب برای ذخیره تنظیمات یا داده‌های کوچک

البته اگر پروژه بزرگ‌تر شود، بهتر است از روش‌های پیشرفته‌تر مانند Hive، Isar، SQLite یا Firebase استفاده شود.

🧩 مدل داده Todo

هر کار در برنامه با استفاده از کلاس "Todo" ساخته می‌شود.

ساختار کلی مدل:

class Todo {
  final String id;
  final String title;
  final String note;
  final TodoPriority priority;
  final bool isDone;
  final DateTime createdAt;
  final DateTime? dueDate;
}

---

🏷️ توضیح فیلدهای مدل Todo

فیلد| نوع داده| توضیح
id| String| شناسه یکتا برای هر کار
title| String| عنوان کار
note| String| توضیح کوتاه کار
priority| TodoPriority| اولویت کار
isDone| bool| وضعیت انجام شدن
createdAt| DateTime| تاریخ ایجاد کار
dueDate| DateTime?| تاریخ انجام کار

---

🎯 enum مربوط به اولویت

در پروژه برای اولویت‌ها از enum استفاده شده است.

enum TodoPriority {
  low,
  normal,
  high,
}

این کار باعث می‌شود مقدارهای اولویت محدود و مشخص باشند و احتمال خطا کمتر شود.

---

🔄 متد copyWith

در کلاس Todo یک متد به نام "copyWith" وجود دارد.

این متد برای ساخت نسخه جدیدی از یک Todo استفاده می‌شود، بدون اینکه لازم باشد همه اطلاعات دوباره از اول نوشته شود.

کاربرد اصلی این متد در موارد زیر است:

- ویرایش یک کار
- تغییر وضعیت انجام شدن
- تغییر تاریخ انجام
- تغییر اولویت

نمونه استفاده:

todos[index] = selectedTodo.copyWith(
  isDone: !selectedTodo.isDone,
);

---

💾 تبدیل Todo به JSON

برای اینکه بتوانیم لیست کارها را داخل کش ذخیره کنیم، باید هر Todo را به JSON تبدیل کنیم.

نمونه خروجی JSON:

{
  "id": "123456789",
  "title": "تمرین Flutter",
  "note": "تمرین ساخت ویجت‌ها",
  "priority": "high",
  "isDone": false,
  "createdAt": "2026-06-27T12:00:00.000",
  "dueDate": "2026-06-28T12:00:00.000"
}

📥 خواندن Todo از JSON

هنگام باز شدن برنامه، اطلاعات از کش خوانده می‌شود. چون اطلاعات به صورت JSON ذخیره شده‌اند، باید دوباره به آبجکت Todo تبدیل شوند.

برای این کار از factory constructor استفاده شده است.

🧠 منطق ذخیره‌سازی داده‌ها

فرآیند ذخیره‌سازی به این شکل است:

1. کاربر یک تغییر در لیست ایجاد می‌کند
2. لیست Todoها به JSON تبدیل می‌شود
3. JSON به String تبدیل می‌شود
4. String داخل SharedPreferences ذخیره می‌شود

---

🔁 منطق خواندن داده‌ها

زمانی که برنامه اجرا می‌شود:

1. تابع "initState" اجرا می‌شود
2. داده‌ها از SharedPreferences خوانده می‌شوند
3. اگر داده‌ای وجود داشته باشد، decode می‌شود
4. JSON به لیست Todo تبدیل می‌شود
5. صفحه با داده‌های ذخیره‌شده به‌روزرسانی می‌شود

⚠️ باگ‌های نسخه قبلی

در نسخه قبلی چند ایراد وجود داشت که در نسخه جدید رفع شده‌اند.

1. ذخیره نشدن کار جدید

در نسخه قبلی، کد مربوط به افزودن و ویرایش کارها کامنت شده بود. به همین دلیل وقتی کاربر روی دکمه افزودن یا ذخیره تغییرات می‌زد، فقط Bottom Sheet بسته می‌شد و هیچ کاری اضافه یا ویرایش نمی‌شد.

در نسخه جدید این مشکل حل شده است.

---

2. ذخیره نشدن داده‌ها بعد از بستن برنامه

در نسخه قبلی داده‌ها فقط داخل RAM بودند. بنابراین بعد از بستن برنامه، تمام کارها از بین می‌رفتند.

در نسخه جدید با استفاده از "shared_preferences" داده‌ها داخل حافظه محلی ذخیره می‌شوند.

---

3. پاک نشدن تاریخ انجام

در نسخه قبلی برای حذف تاریخ انجام، باید دقت می‌شد که مقدار null درست مدیریت شود.

در نسخه جدید از پارامتر "clearDueDate" در متد "copyWith" استفاده شده است.

---

4. احتمال خطا در DatePicker

🧠 نحوه فیلتر کردن لیست

برای فیلتر کردن کارها از enum استفاده شده است.

enum TodoFilter { all, active, done }

متد فیلتر:

List<Todo> get filteredTodos {
  switch (selectedFilter) {
    case TodoFilter.all:
      return todos;
    case TodoFilter.active:
      return todos.where((todo) => !todo.isDone).toList();
    case TodoFilter.done:
      return todos.where((todo) => todo.isDone).toList();
  }
}

- داده خراب نشده باشد

🧠 نکته آموزشی مهم

در Flutter زمانی که داده‌ای تغییر می‌کند، باید از "setState" استفاده کنیم تا صفحه دوباره ساخته شود.

مثلاً هنگام افزودن کار:

setState(() {
  todos.insert(0, newTodo);
});

بعد از آن برای ذخیره دائمی تغییرات:

saveTodosToCache();

🧠 نکته مهم درباره JSON

چون SharedPreferences نمی‌تواند مستقیماً لیست آبجکت‌ها را ذخیره کند، باید لیست Todoها را به JSON تبدیل کنیم.

فرآیند تبدیل:

List<Todo> → List<Map> → JSON String → SharedPreferences

فرآیند خواندن:

SharedPreferences → JSON String → List<Map> → List<Todo>

🧠 چرا id لازم است؟

هر Todo باید یک شناسه یکتا داشته باشد تا بتوان آن را دقیق پیدا کرد.

مثلاً برای ویرایش یا حذف، برنامه با استفاده از id آیتم موردنظر را پیدا می‌کند.

final index = todos.indexWhere((todo) => todo.id == selectedTodo.id);

اگر id وجود نداشته باشد، ممکن است هنگام وجود چند کار مشابه، برنامه کار اشتباهی را حذف یا ویرایش کند.

---

🧠 چرا DateTime به String تبدیل می‌شود؟

چون JSON به صورت مستقیم نوع DateTime را ذخیره نمی‌کند. بنابراین باید تاریخ را به String تبدیل کنیم.

برای ذخیره:

createdAt.toIso8601String()

برای خواندن:

DateTime.tryParse(json['createdAt'])

🎤 متن کوتاه برای توضیح پروژه در ارائه

این پروژه یک اپلیکیشن مدیریت کارهای روزانه است که با Flutter طراحی شده است. کاربر می‌تواند وظایف جدید اضافه کند، آن‌ها را ویرایش یا حذف کند، برای هر کار اولویت و تاریخ انجام مشخص کند و وضعیت انجام شدن کارها را تغییر دهد. همچنین برنامه دارای فیلتر برای نمایش همه کارها، کارهای فعال و کارهای انجام‌شده است. اطلاعات برنامه با استفاده از SharedPreferences در حافظه محلی ذخیره می‌شود، بنابراین بعد از بسته شدن برنامه، داده‌ها از بین نمی‌روند.

🧾 متن بلندتر برای توضیح پروژه در ارائه

در این پروژه یک اپلیکیشن Todo List فارسی و راست‌چین با استفاده از Flutter ساخته شده است. هدف برنامه مدیریت ساده و سریع کارهای روزانه است. کاربر می‌تواند برای هر کار عنوان، توضیح، اولویت و تاریخ انجام مشخص کند. همچنین امکان تغییر وضعیت کارها به انجام‌شده یا در حال انجام وجود دارد.

در طراحی رابط کاربری از Material Design 3 استفاده شده و ظاهر برنامه شامل کارت‌های مدرن، گرادیان پس‌زمینه، انیمیشن‌های نرم و فیلترهای تعاملی است. برای نمایش لیست کارها از ListView.builder استفاده شده و هر آیتم به صورت یک کارت جداگانه طراحی شده است.

یکی از قابلیت‌های مهم پروژه ذخیره‌سازی اطلاعات در حافظه محلی است. برای این کار از پکیج SharedPreferences استفاده شده است. داده‌های Todo ابتدا به JSON تبدیل می‌شوند و سپس به صورت String ذخیره می‌شوند. هنگام اجرای دوباره برنامه، داده‌ها از کش خوانده شده و دوباره به لیست Todo تبدیل می‌شوند.

این پروژه نمونه خوبی برای تمرین مفاهیمی مانند StatefulWidget، setState، مدل‌سازی داده، enum، JSON، SnackBar، Bottom Sheet و ذخیره‌سازی محلی در Flutter است.
